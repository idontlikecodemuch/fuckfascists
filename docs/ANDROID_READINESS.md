# Android Readiness

Use this before emulator or friend-device testing. Last full emulator pass:
**2026-09-21** (Pixel 8 AVD, Android 15 / API 35, arm64, debug build, no
Google Maps key). Session notes and the prioritized findings list live in
`docs/PROGRESS.md` under that date.

## Current Posture

- The app runtime does **not** require `FEC_API_KEY`. `FECClient` runs in anonymous mode when no key is present.
- Android Google Maps is separate from FEC/OpenFEC. With no `GOOGLE_MAPS_ANDROID_API_KEY`, Android renders a mapless search fallback instead of mounting the native map. Every other flow (search, business card, avoid, Track, Scan, Scorecard, share, archive, Info, beta tools) works without a key and was exercised on the emulator.
- Native maps use a dark presentation on both OSs. Android gets the Google Maps dark style only when the native map is enabled; the no-key fallback is already dark.
- `android/` is generated by `expo prebuild` and is **not** committed and **not** gitignored yet (open decision, see PROGRESS.md). Never stage it.
- `expo-build-properties` now sets `android.minSdkVersion = 29`. The old `expo.android.minSdkVersion` key in `app.json` was silently ignored by Expo, so earlier builds shipped minSdk 24 and the File-Based-Encryption guarantee in `CLAUDE.md` did not actually hold. Verify after any config change with `apkanalyzer manifest min-sdk <apk>`.
- `android.blockedPermissions` strips permissions that Expo module manifests merge in but the app never uses: `RECORD_AUDIO` (expo-camera), `READ_MEDIA_IMAGES/VIDEO/AUDIO/VISUAL_USER_SELECTED` and `READ_EXTERNAL_STORAGE` (expo-media-library / expo-screen-capture), and `SYSTEM_ALERT_WINDOW`. Saving screenshots and scorecards uses write-only media access, which needs no runtime prompt on Android 13+.
- The iOS-only `MapKitSearch` module is safe on Android: the JS wrapper returns `[]`, and Android POI matching uses `react-native-maps` `onPoiClick`.

## Known Build Blocker: react-native 0.76.0 vs 0.76.9

A fresh `expo prebuild` + Gradle build fails in `expo-modules-core:compileDebugKotlin`:

```
This version (1.5.15) of the Compose Compiler requires Kotlin version 1.9.25
but you appear to be using Kotlin version 1.9.24
```

`react-native@0.76.0` pins the Kotlin Gradle plugin to 1.9.24 through
`@react-native/gradle-plugin`; Expo SDK 52 expects `react-native@0.76.9`,
which pins 1.9.25 (verified in both packages' `libs.versions.toml`).
`expo-modules-core@2.2.3` ships Compose compiler 1.5.15 and needs 1.9.25.

- **Real fix (needs owner sign-off, touches iOS pods):** `npx expo install react-native@0.76.9`, then `npm install && cd ios && pod install`, re-verify iOS. `npx expo install --check` also flags `expo-sqlite` and `react-native-safe-area-context` drift; only the RN bump is required for Android.
- **Local workaround used on 2026-09-21** (in the generated, uncommitted `android/build.gradle`):

  ```sh
  sed -i '' "s#classpath('org.jetbrains.kotlin:kotlin-gradle-plugin')#classpath(\"org.jetbrains.kotlin:kotlin-gradle-plugin:\${kotlinVersion}\")#" android/build.gradle
  ```

- Until the RN bump lands, **EAS Android builds (`device`, `android-preview`) will fail** because EAS runs prebuild fresh and the sed above is local only.

## Local Emulator Setup (verified 2026-09-21, macOS arm64, Homebrew, no sudo)

Nothing Android-related was preinstalled on the dev Mac. These steps got an
emulator running the debug build without Android Studio and without `sudo`.

1. JDK 17 (keg-only, no symlinks needed) and the SDK command-line tools:

   ```sh
   brew install openjdk@17
   brew install --cask android-commandlinetools
   ```

   If `openjdk@17` fails with `Cannot link fontconfig`, rerun the same command;
   the second run completes.

2. Environment. Put these in `~/.zshrc` (or source them per shell):

   ```sh
   export JAVA_HOME="/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home"
   export ANDROID_HOME="$HOME/Library/Android/sdk"
   export ANDROID_SDK_ROOT="$ANDROID_HOME"
   export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
   ```

3. SDK components into the standard location (Android Studio, if installed
   later, will find and reuse this directory). About 8 GB.

   ```sh
   yes | sdkmanager --sdk_root="$ANDROID_HOME" --licenses
   sdkmanager --sdk_root="$ANDROID_HOME" --install \
     "cmdline-tools;latest" "platform-tools" "platforms;android-35" \
     "build-tools;35.0.0" "emulator" "ndk;26.1.10909125" "cmake;3.22.1" \
     "system-images;android-35;google_apis;arm64-v8a"
   ```

   `google_apis` (not `google_apis_playstore`) ships Google Play services, so
   Google Maps would render if a key were ever added, and `adb root` works.

4. Create and boot the AVD:

   ```sh
   echo no | avdmanager create avd -n Pixel_8_API_35 \
     -k "system-images;android-35;google_apis;arm64-v8a" -d pixel_8
   emulator -avd Pixel_8_API_35 -no-boot-anim -gpu auto &
   adb wait-for-device
   ```

   First cold boot takes 1-2 minutes. If native map tiles or the camera
   virtual scene glitch on Apple Silicon, Google's guidance is `-gpu
   swiftshader_indirect`. To put a barcode in front of the emulated camera:
   `-virtualscene-poster wall=/path/to/ean13.png` (see Scan below).

5. Native project, dependencies, build (apply the Kotlin workaround above
   until the RN bump lands):

   ```sh
   npm ci
   npx expo prebuild --platform android --no-install
   cd android && ./gradlew :app:assembleDebug -PreactNativeArchitectures=arm64-v8a
   ```

   Limiting `reactNativeArchitectures` to `arm64-v8a` skips three unused NDK
   targets and roughly quarters the C++ build time for emulator work. First
   build is ~6 minutes on an M-series Mac after Gradle/NDK downloads.

6. Run:

   ```sh
   adb install -r android/app/build/outputs/apk/debug/app-debug.apk
   adb reverse tcp:8081 tcp:8081
   npx expo start --port 8081        # Metro, separate terminal
   adb shell am start -n com.fckapp.fck/.MainActivity
   ```

Emulator gotchas learned the hard way:

- Debug builds fetch every image from Metro on first display, so a screen can
  render for 1-3 s with images missing. Wait before judging a "missing asset".
- `adb root` restarts adbd and silently drops `adb reverse`; re-run it.
- `adb shell am force-stop` also cancels the app's AlarmManager alarms, so
  scheduled notifications vanish until the app reschedules them on next launch.
- Changing the clock with `adb shell date` does not fire RTC alarms; use
  `adb shell cmd alarm set-time <epoch-ms>` and restore afterwards. Backgrounding
  the debug app mid-bundle-load can trigger an ANR kill; wait for `Running "main"`
  in logcat first.
- Nothing vibrates on the emulator, so every haptic is a silent no-op.

## Known Differences From iOS

- Android POI taps provide name + coordinate only; iOS can also use MapKit URL/domain hints.
- No-key Android builds are search-only on the Map tab. That is intentional for early simulator/friend testing without a Google Maps SDK key.
- Android scorecard screenshot parity is post-capture: screenshot detection opens share with the clean cached card, but the original screenshot still lands in Photos. Works on API 34+ only.
- `SafeAreaView` from `react-native` is a no-op on Android; screens rely on the opaque `#070B12` status bar from the theme instead. Fine under Expo SDK 52 (targetSdk 34). Revisit when moving to SDK 53+, which forces edge-to-edge.
- Local notifications never show while the app is foregrounded on either OS because no `Notifications.setNotificationHandler` is registered. The dev harness "fire nudge now" therefore shows nothing in the foreground. Cross-platform, not Android-specific.
- `AlarmManager` delivers expo-notifications triggers inexactly (up to +1 h). iOS is exact. The "synchronized global drop moment" is up to an hour late on Android.

## Map Without a Google Key — Decision Record (researched 2026-09-21)

Owner goal: no key, $0, privacy-preserving. Findings, with sources in the session notes:

1. **Google Maps SDK for Android is $0 and unlimited** for map loads that carry no Map ID (the app uses legacy JSON `customMapStyle`, so it qualifies), and `onPoiClick` costs nothing. But Google still requires a Cloud Billing account with a payment method on file even at $0. That alone fails the "no key" goal.
2. **Raster OSM tiles over `react-native-maps` without a valid key do not work** on Android: the Google map view must authenticate before any overlay draws (react-native-maps #5156, #5413 on this exact stack; maintainer statement that a provider is required). Dead end.
3. **`expo-maps`** is SDK 53+, alpha, and requires a Google key on Android. Not an option on SDK 52.
4. **MapLibre + OpenFreeMap is the only literally key-free, $0 path.** `@maplibre/maplibre-react-native@10.4.2` (last v10; v11 requires Expo 54 / RN 0.80), Fabric via interop layer, config plugin included. OpenFreeMap: no keys, no limits, no IP logging, commercial use allowed, attribution auto-added; risk is a solo-maintained service with no SLA. POI name on tap is feasible: OpenMapTiles `poi` layer carries `name`; use the `liberty` or `bright` style (Positron has no POI layer) and `queryRenderedFeaturesAtPoint` with explicit layer ids `['poi_r1','poi_r7','poi_r20']` at zoom ≥ 15 (Android ignores an empty layer list). Rough scope: 6 files on the Map feature, Android-only (keep MapKit on iOS to preserve domain enrichment). OSM's own raster tile servers remain off-limits for apps.

Recommendation: keep the search-only fallback for now; if native Android map parity becomes a priority, prototype MapLibre + OpenFreeMap Android-only before committing (one marker + one POI query on the emulator is enough to de-risk the Fabric interop).
